🗄️ Skema Database & Row Level Security (RLS)

Model data dirancang secara relasional ketat dengan kebijakan akses multi-tenant berbasis peran (RBAC):

Nama Tabel Deskripsi Entitas Aturan Keamanan (RLS Policy)
profiles Menyimpan profil pengguna, NIP/NIK, dan role (admin, guru, view_only). User dapat membaca/edit profil sendiri; Admin memiliki akses baca seluruh user.
schools Data institusi SMK, NPSN, akreditasi, koordinat lat/lng, dan jurusan. Admin memiliki akses CRUD penuh; Guru dapat membaca data sekolah terafiliasi.
companies Daftar Mitra Industri / PKT, kuota magang, sektor, dan lokasi cabang. Dapat dibaca oleh semua pengguna terotentikasi; CRUD dikelola oleh Admin.
students Data siswa, NISN, jurusan, status penempatan, dan riwayat kompetensi. Guru dapat mengelola siswa sekolahnya; Admin memiliki visibilitas global.
internships Kontrak penempatan magang aktif yang menghubungkan siswa, guru, dan industri. Terkunci per sekolah pembimbing dan pengelola program.
evaluations Penilaian teknis & non-teknis siswa, absensi, dan catatan evaluasi berkala. Hanya dapat diinput oleh Guru Pembimbing atau Mentor Industri terkait.
⚠️ Aturan RLS & Safe Migration
Semua query ke tabel harus mematuhi policy RLS. Saat membuat query baru pada backend/server loaders, pastikan selalu menggunakan token autentikasi pengguna atau RPC function terisolasi untuk mencegah eksfiltrasi data antar sekolah.

🗺️ Integrasi Google Maps & Geocoding

Komponen GoogleMapsView (src/components/app/google-maps-view.tsx) mendukung visualisasi geospasial real-time:

  • Pin Clustering: Mengelompokkan lokasi sekolah (warna biru) dan mitra industri (warna hijau/oranye) untuk mempermudah identifikasi kepadatan wilayah.
  • Radius & Route Lines: Menampilkan garis rute antara sekolah asal dan kantor magang mitra dengan kalkulasi jarak tempuh.
  • Fallback Geocoding: Dilengkapi modul otomatis untuk mengonversi alamat string menjadi koordinat Lat/Lng saat import file Excel.

📝 Architecture Decision Records (ADRs)

Keputusan teknis penting yang mendasari arsitektur VokasiFlow AI:

ADR-001: Adopsi TanStack Start + Nitro SSR Engine

Status: Diterima (Accepted) | Tanggal: 2026-08-16

Konteks: Dibutuhkan routing type-safe dan render performan dengan kapabilitas Server-Side Rendering (SSR) untuk data analitik vokasi berskala besar.

Keputusan: Memilih TanStack Start dengan Nitro engine untuk kompatibilitas deployment multi-target (Vercel, Node, Edge).

ADR-002: Supabase PostgreSQL dengan Row Level Security (RLS)

Status: Diterima (Accepted) | Tanggal: 2026-08-16

Konteks: Perlunya pemisahan data antar sekolah (multi-tenancy) dan perlindungan data privasi siswa (NISN, nilai evaluasi).

Keputusan: Menerapkan RLS granular pada level database PostgreSQL sehingga data hanya dapat diakses sesuai role pengguna.

ADR-003: Client-Side Excel Ingestion dengan SheetJS (xlsx)

Status: Diterima (Accepted) | Tanggal: 2026-08-20

Konteks: Guru dan Admin sering mengunggah ratusan baris data siswa sekaligus dalam format spreadsheet `.xlsx` / `.xls`.

Keputusan: Parsing dilakukan in-browser secara reaktif dengan validasi skema sebelum melakukan batch insert ke Supabase, mengurangi beban server.

🚀 Alur Operasional Sistem (End-to-End Workflow)

VokasiFlow AI menghubungkan alur kerja program magang secara terintegrasi:

  1. 1. Registrasi & Inisialisasi Data Sekolah

    Admin mendaftarkan profil institusi SMK, jurusan kejuruan, serta data mitra industri (DUDI / PKT) yang siap menerima peserta magang.

  2. 2. Unggah Data Siswa via Excel

    Guru Pembimbing mengunggah data siswa per kelas menggunakan template Excel bawaan untuk dipetakan ke sistem dalam hitungan detik.

  3. 3. Penempatan Magang & Rekomendasi AI

    Sistem merekomendasikan lokasi industri yang cocok berdasarkan kompetensi siswa dan ketersediaan kuota. Admin memvalidasi penempatan.

  4. 4. Monitoring Lapangan & Peta Geospasial

    Guru memantau rute dan lokasi magang siswa melalui peta interaktif serta memverifikasi catatan harian dan absensi kehadiran.

  5. 5. Evaluasi & Laporan Analitik Akhir

    Input penilaian kompetensi teknis dan soft skill, disusul penerbitan sertifikat dan laporan evaluasi keselarasan kurikulum (Link & Match).

❓ Tanya Jawab & Solusi Kendala (FAQ)

Bagaimana jika titik koordinat sekolah / mitra tidak muncul di peta?

Pastikan penulisan kolom alamat mencantumkan nama kota/kabupaten lengkap (contoh: Jl. Pemuda No. 10, Semarang, Jawa Tengah). Sistem geocoding otomatis mengonversi alamat tersebut menjadi titik koordinat.

Apakah Guru dapat mengubah data sekolah lain?

Tidak. Berdasarkan kebijakan keamanan Row Level Security (RLS), setiap Guru hanya memiliki wewenang untuk melihat dan mengelola data siswa dari sekolah tempatnya mengajar.

Bagaimana cara mendapatkan rekomendasi penempatan AI?

Buka menu Rekomendasi AI pada portal Admin, lalu klik tombol "Generate AI Recommendation". AI akan menganalisis kecocokan jurusan dan kuota secara otomatis.
