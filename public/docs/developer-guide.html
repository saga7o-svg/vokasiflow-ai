🎯 Nilai Utama & Cakupan Sistem

VokasiFlow AI bukan Learning Management System (LMS) atau sistem ujian daring, melainkan Enterprise SaaS B2B untuk otomasi administrasi magang, pemetaan spasial institusi-industri, analisis kecerdasan buatan (*AI recommendation* & *forecasting*), serta evaluasi kompetensi vokasi berbasis data.

4. Skema Basis Data & Row Level Security (RLS)

PostgreSQL skema dirancang dengan prinsip relasional ketat dan isolasi multitenant:

Nama Tabel Kolom Kunci Deskripsi & Relasi
profiles id (FK auth.users), role, school_id, full_name Menyimpan metadata profil pengguna dan perannya (admin, guru, siswa, industri).
schools id, npsn, name, latitude, longitude, accreditation Master data SMK / Politeknik dan koordinat GPS untuk pemetaan rute.
companies & branches id, company_name, sector, address, quota Data institusi mitra industri (DUDI) dan titik cabang lokasi PKL.
students id, nisn, full_name, school_id, major, gpa, skills Data siswa, kompetensi teknis, dan keterhubungannya dengan sekolah asal.

internship_activities id, placement_id, date, activity_description, attendance Log harian jurnal PKL dan absensi siswa yang diverifikasi guru.

5. Stored Procedures & Security Definer RPC

Untuk memfasilitasi pembuatan akun oleh Admin tanpa merusak sesi autentikasi yang sedang berjalan di browser, sistem memanfaatkan RPC function khusus:

SQL RPC: admin_create_user_with_metadata 
CREATE OR REPLACE FUNCTION public.admin_create_user_with_metadata(
  new_email TEXT,
  new_password TEXT,
  new_role TEXT,
  new_full_name TEXT,
  new_school_id UUID DEFAULT NULL,
  new_nip TEXT DEFAULT NULL,
  new_phone TEXT DEFAULT NULL
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, auth
AS $$
DECLARE
  new_user_id UUID;
BEGIN
  -- 1. Cek hak akses pemanggil (harus admin)
  IF NOT public.is_admin() THEN
    RAISE EXCEPTION 'Akses ditolak: Hanya Admin yang dapat membuat akun';
  END IF;

  -- 2. Insert ke auth.users
  INSERT INTO auth.users (id, email, encrypted_password, email_confirmed_at, raw_user_meta_data)
  VALUES (
    gen_random_uuid(),
    new_email,
    crypt(new_password, gen_salt('bf')),
    now(),
    jsonb_build_object('role', new_role, 'full_name', new_full_name)
  )
  RETURNING id INTO new_user_id;

  -- 3. Upsert ke public.profiles
  INSERT INTO public.profiles (id, email, role, full_name, school_id, nip, phone)
  VALUES (new_user_id, new_email, new_role, new_full_name, new_school_id, new_nip, new_phone);

  RETURN jsonb_build_object('success', true, 'user_id', new_user_id);
END;
$$;

Keputusan Arsitektur (Architecture Decision Records)

ADR-001: Adopsi TanStack Router Berbasis File

Diterima / Accepted

Konteks: Aplikasi membutuhkan sistem routing type-safe untuk memisahkan guard akses peran Admin dan Guru secara terisolasi.

Keputusan: Menggunakan TanStack Router dengan konvensi penamaan src/routes/_authenticated/app.admin.*.tsx dan app.guru.*.tsx.

Dampak: Menghilangkan bug broken-link saat refactoring nama rute dan mempercepat navigasi SPA.

ADR-002: Row Level Security (RLS) pada PostgreSQL Supabase

Diterima / Accepted

Konteks: Mengamankan data multitenant siswa SMK agar guru dari Sekolah A tidak dapat membaca atau mengubah data Sekolah B.

Keputusan: Setiap tabel sensitif dilindungi dengan policy RLS berbasis auth.uid() dan perbandingan profiles.school_id.

ADR-003: Visualisasi Geospasial Google Maps Platform

Diterima / Accepted

Konteks: Rekomendasi penempatan magang harus mempertimbangkan jarak riil perjalanan siswa ke lokasi cabang mitra industri.

Keputusan: Integrasi langsung Google Maps JavaScript API dengan marker clustering, penghitungan Haversine/Distance Matrix, dan visualisasi rute.

ADR-004: Ingesti Excel Massal di Sisi Klien (SheetJS)

Diterima / Accepted

Konteks: Pengguna sering mengunggah ribuan baris data siswa dengan format bervariasi.

Keputusan: Parsing dan validasi error dilakukan instan di browser client sebelum dikirim ke database dalam bentuk batch insert teroptimasi.
